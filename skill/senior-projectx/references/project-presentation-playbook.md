# 客户模板汇报

先打开本次采用的模板和同伴已确认的代表页。记录页号、页面比例、标题区、正文栏宽、图名位置、图例、脚注和页码。已打开且正在编辑的源稿以用户实际保存的版本为准。合稿前核对负责的章节、顺序和版式。章节汇报一般直接进入技术问题。

## 从工程问题进入证据

一页围绕一个需要回答的问题。方法页讲清输入如何经由模型产生可用结果，算例页用同一对象的基准、约束、差值说明变化。先使用已认可的结果对象，保留相应单位、分母、年份、场景和求解边界。对于看似单薄的图，优先在现有坐标内补入同源的配对差值、阈值、适用时段或异常点。真实信息量有限时使用读得清的小图或表。复杂主图可独立成页，互补的小图可成组。

例如，持续减载页先问「四小时服务窗内能维持多少减载」。用同轴温度轨迹和功率变化标出室温触及限值的时刻，再解释缩短服务窗后能承接哪类任务。页面保留理解这个判断所需的条件。完整公式推导有独立用途时放在方法页或附页。讲解稿按已确认的页序组织。

## 按实际版面安排图名、图例和连接线

用模板当前的文字栏、图框和图名位置。如果客户模板将图名放在图下，确保每个图与其图名、单位可一眼配对。页内的文字字号按演示尺寸决定。保留图片长宽比，地图纵横等比缩放，环形图保持圆形。多区画像在地图、图例、份额环中使用同一编码，份额分母按同年同类资源核对。

图例有空间时先试一行，用真实字体测量图例色块、标签和各项间距。将需要更多空间的图例放到可用宽区，保证字体可读。检查共用基线、对齐和图例与数据区的距离。自定义图例的颜色、线型和标签应与原生系列绑定。箭头端点对准实际对象，检查跨区线和图名之间的留白。

## 局部修订和重开检查

先定位到目标页及对象，核对允许改动的是尺寸、样式、文字还是内容。只调图例时，保留数据、颜色映射、轴范围以及地图投影。用 [原生导出](../scripts/project_ppt_roundtrip.ps1) 在测试副本里保存重开，按原页面比例导出每页，从成稿查看实际字号、裁剪、遮挡、图例、页码、标签、下标、公式和箭头。枚举对象只能说明对象类型和数量，原生文本、表格与图表工作簿的编辑持久性另按 [Office 流程](../tests/office/README.md) 检查。

布局修订前后可比较原生图表的缓存数据与引用、嵌入工作簿、表格内容、图片及 OLE 对象：

~~~powershell
python scripts/audit_pptx_evidence.py --source source.pptx --revised revised.pptx --json-out review/ppt_evidence.json
~~~

核对发生变化的页号及对象类别。嵌入工作簿重存可能改变包字节，此时打开工作簿比较真实值、公式和引用。重新编码的媒体也须在最终页核对。脚本按演示顺序比较；有意调序或增减页时，先按已确认的页面映射检查。新版布局从保存重开后的文件验收，报告和研究计算复用当前可追溯的结果。
